# Sim teleoperation does not use ROS; outputs are pluggable

The real hands are driven through ROS 2 (Tesollo's driver), so using ROS in the sim teleop looks natural. We don't: ROS 2 Humble's `rclpy` only runs on the system Python 3.10, while the Twin runs on Python 3.12 to match Newton / Isaac Lab, so a ROS node could not live in the simulation process and would only add a bridge process. The real arms are not driven through ROS anyway (ZMQ to `impedance_controller`). Instead, teleoperation is split into input sources (Glove finger angles over ZMQ from the MANUS client, Wrist board poses over ZMQ from the pose estimator), a pure-Python core (Finger retargeting + arm IK producing per-Limb joint targets), and outputs. The sim is the first output; a real-robot output (Hand targets to ROS 2, Arm targets to the impedance controller) is added later without touching the core.
